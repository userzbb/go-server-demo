# Omega Server 开发规范

本文档是项目的“宪法”，所有开发活动必须遵守。

## 1. Git 工作流规范
- **分支模型**：`main`（生产） / `develop`（开发） / `feature/*`（功能分支）
- **提交信息格式**：`<type>: <description>`
  - `feat:` 新功能
  - `fix:` Bug 修复
  - `docs:` 文档更新
  - `refactor:` 重构
  - `chore:` 构建/工具变动
- **合并策略**：功能分支合并到 `develop` 必须使用 `--no-ff`

## 2. 代码风格与质量门禁
- **格式化**：必须通过 `gofmt` 和 `goimports`
- **Lint 门禁**：提交前必须通过 `make lint`（零警告）
- **命名规范**：
  - 包名：全小写，无下划线（如 `network`）
  - 公开函数：大驼峰（必须写注释）
  - 私有变量：小驼峰

## 3. 错误处理策略
- 禁止使用 `_` 忽略 error（`Close` 等特殊场景除外）
- 使用 `fmt.Errorf("xxx: %w", err)` 包装错误
- 运行时禁止 panic，必须返回 error 并优雅降级

## 4. 日志规范
- 使用 `Zap`（高性能结构化日志），禁止使用标准库 `log`
- 日志级别：`Debug` / `Info` / `Warn` / `Error`
- 日志必须包含 `trace_id`（用于链路追踪）

## 5. 测试规范
- 核心模块测试覆盖率 ≥ 70%
- 使用表驱动测试（Table-Driven Tests）
- 单元测试不能依赖外部环境（使用 Mock）

## 6. 配置管理规范
- 优先级：命令行参数 > 环境变量 > 配置文件 > 默认值
- 敏感信息（密码/密钥）禁止写入配置文件，必须通过环境变量注入
